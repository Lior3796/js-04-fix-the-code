# תרגיל 4 - JavaScript "Fix the Code" Challenges 🛠

התוכניות בריפו הזה רצות בלי שגיאות תחביר, אבל הן לא עושות את מה שהן אמורות לעשות בגלל טעויות לוגיות. המשימה שלכן:

- ✅ למצוא את הבעיות
- ✅ לתקן את הקוד כך שיתנהג כמו שצריך
- ✅ מותר לשנות את הלוגיקה של הפונקציות, תנאים, לולאות, `import` ו-`export` - אבל לשמור על המבנה הכללי

בכל אתגר יכולים להיות כמה קבצים.

## איך מתחילים

1. לוחצים למעלה על **Use this template** ← **Create a new repository**, ויוצרים ריפו משלכן.
2. עושים `git clone` לריפו החדש ופותחים אותו ב-VS Code.
3. בטרמינל מריצים פעם אחת: `npm install` (צריך Node בגרסה 20 ומעלה. בודקים עם `node -v`).
4. כל אתגר נמצא בתיקייה משלו (`challenge1-greeting`, `challenge2-discount` וכו'). מתקנים את הקוד בקבצים שבתיקייה.
5. כדי לראות מה תוכנית מדפיסה, מריצים אותה מהתיקייה הראשית של הפרויקט, למשל:

```bash
node challenge1-greeting/main.js
```

> הקבצים משתמשים ב-`import` / `export` (ES Modules). בגלל זה ב-`package.json` כתוב `"type": "module"` - אל תמחקו את השורה הזו.

## איך בודקים

```bash
npm test
```

- בהתחלה כל הטסטים אדומים (✘). כל טסט מתחיל במספר האתגר שהוא בודק.
- מתחת לכל טסט שנכשל כתוב מה לא עבד, ולפעמים גם מה הקוד שלכן החזיר בפועל (`got ...`).
- כשכל הטסטים ירוקים (✔) מופיעה ההודעה **✅ המשימה אושרה** ואפשר לעבור למשימה הבאה.
- אחרי `git push` הטסטים רצים גם ב-GitHub (לשונית Actions). וי ירוק ליד ה-commit = המשימה אושרה.
- מריצים טסט של אתגר אחד בלבד: `node --test test/challenge2.test.js`

> אל תשנו את הקבצים בתיקייה `test/`.

### 🌟 אתגר 1: Incorrect User Greeting System
המערכת אמורה לברך משתמשים חדשים פעם אחת בלבד. משתמשים שחוזרים צריכים להיות מזוהים ולקבל ברכה אחרת.

❌ **מה קורה עכשיו:**
- משתמשים חדשים מקבלים את ההודעה "Welcome back"
- כל משתמש נוסף לרשימה, גם אם הוא כבר נמצא בה

✅ **מה צריך לקרות:**
- משתמשים חדשים: `Welcome, Alice!`
- משתמשים שחוזרים: `Welcome back, Alice!`

הרצה של `main.js` צריכה להדפיס:
```
Welcome, Alice!
Welcome, Bob!
Welcome back, Alice!
```

### 🌟 אתגר 2: Faulty Product Discount Calculator
מחילים הנחה לפי מחיר המוצר: מוצרים מעל 100 מקבלים 10% הנחה, מוצרים מתחת ל-20 לא מקבלים הנחה, וכל השאר מקבלים 5%.

❌ **מה קורה עכשיו:** המחירים מתחת ל-20 גורמים ללוגיקת הנחה שגויה.

✅ **מה צריך לקרות:** ההנחות מחושבות לפי טווחי המחירים, לפי הכללים.

הרצה של `app.js` צריכה להדפיס `135`, `15`, `47.5`.

שימו לב לגבולות: מחיר של בדיוק 100 הוא לא "מעל 100", ומחיר של בדיוק 20 הוא לא "מתחת ל-20" - שניהם מקבלים 5% הנחה.

### 🌟 אתגר 3: Broken To-Do List Filter
מסננים מתוך הרשימה את המשימות שכבר הושלמו.

❌ **מה קורה עכשיו:** הפונקציה מחזירה את המשימות שהושלמו במקום את אלו שעוד מחכות.

✅ **מה צריך לקרות:** מוחזרות רק המשימות שבהן `completed` הוא `false`.

### 🌟 אתגר 4: Temperature Tracker Malfunction
עוקבים אחרי טמפרטורות ומדפיסים את הממוצע אחרי כל מדידה חדשה.

❌ **מה קורה עכשיו:** מודפס `NaN` או ממוצע לא נכון (או שהתוכנית קורסת) בגלל חישוב שגוי של הסכום.

✅ **מה צריך לקרות:** ממוצע מדויק אחרי כל הוספה. הרצה של `main.js` צריכה להדפיס:
```
Average temperature: 20
Average temperature: 22.5
Average temperature: 25
```

### 🌟 אתגר 5: Incomplete Shopping Cart Total
מחשבים את המחיר הכולל של הפריטים בעגלה, לפי המחיר והכמות.

❌ **מה קורה עכשיו:** רק המחירים מחוברים, והכמויות לא נלקחות בחשבון.

✅ **מה צריך לקרות:** הסכום הכולל הוא המחיר כפול הכמות של כל מוצר. הרצה של `app.js` צריכה להדפיס `14`.

## בדיקה עצמית
- כל תוכנית רצה עם `node` ומדפיסה בדיוק את מה שכתוב למעלה.
- הפונקציות עובדות גם על נתונים אחרים (משתמשים אחרים, מחירים אחרים, משימות ומוצרים שנוספו לרשימה) - לא רק על הדוגמאות.
- `npm test` מסתיים בהודעה **✅ המשימה אושרה**.
